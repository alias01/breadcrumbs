# breadcrumbs v2 — step commands, test-first, contract-first

Status: implemented 2026-10-19 (v2.0.0). Deviations from the draft are under "Implemented differently" at the end.

Three changes, one release:

1. Each step gets its own command; `/breadcrumbs` stays as the auto-flow.
2. Every task is test-first: minimal smoke test, red before green, frozen after red.
3. Stories spanning backend + frontend are contract-first: contract task, then backend, then frontend.

---

## 1. Step commands

### Command set

| Command | Runs | Ends by |
|---|---|---|
| `/breadcrumbs` | Steps 1→4 auto-flow, gates as today | — |
| `bc understand` | Step 1 (lite: folds Step 2, as today) | naming `bc plan` (or `bc build` for lite) |
| `bc plan` | Step 2 | writing the context file, naming `bc build` |
| `bc build` | Step 3 points 0–7 | naming `bc review` |
| `bc review` | Step 3.8 gate: full planned set, review round, commit on approval | naming `bc pr` |
| `bc pr` | Step 4 | — |
| `bc resume` | `resume.md` | naming the next command |
| `bc status` | one-line state + next command; no investigation, no file write | — |
| `bc pause` | Stop-signal trigger: write/backfill file, suggest `/compact` | — |
| `bc why <thing>` | read the matching Task Log / Scope Change / Assumption entry | — |
| `bc rule <text>` | append to `.breadcrumbs/constitution.md` (contradiction check as today) | — |

A command never auto-advances into the next step. Running the next command *is* the gate confirmation;
a plain "yes" at a gate still works inside `/breadcrumbs`.

### Per-platform spelling

Prefix decided as `bc`. Each platform's own command mechanism decides the exact spelling:

| Platform | Mechanism | Spelling |
|---|---|---|
| Claude Code (plugin) | `commands/bc-*.md` at plugin root | `/bc-plan` (also `/breadcrumbs:bc-plan`) |
| Gemini CLI | `.gemini/commands/bc/*.toml` | `/bc:plan` |
| Cursor | `.cursor/commands/bc-*.md` | `/bc-plan` |
| Windsurf | workflows `.windsurf/workflows/bc-*.md` | `/bc-plan` |
| Copilot, Kiro, Cline | no slash commands | say "bc plan" — router maps the phrase |

Claude Code plugin commands are namespaced by plugin name, so a literal `/bc:plan` isn't available
there; `bc-` keeps one spelling across Claude/Cursor/Windsurf. Generated by `build-platforms.mjs`
from one source per command (`skills/breadcrumbs/commands/<name>.md`), same as the router today.

### Command file shape

Each command is thin: precondition check → load the shared core + its step file → run → name next.
Shared core = the parts of `SKILL.md` every step needs (communication style, investigation scope,
caps, context-file triggers, gate waivers). The rest of `SKILL.md` stays with `/breadcrumbs`.

### Preconditions — warn, don't refuse

| Command | Needs | Missing → |
|---|---|---|
| `bc plan` | confirmed Understanding (chat or file) | warn, offer `bc understand`; proceed on "go" |
| `bc build` | Plan + Task Checklist | warn, offer `bc plan`; proceed on "go" → logged under `Gate Waivers` |
| `bc review` | all tasks ticked | list unticked tasks, offer `bc build` |
| `bc pr` | commits on the story branch | none → say so, offer `bc review`; a branch built without breadcrumbs is fine — draft from commits |

Proceeding past a missing step is a gate waiver (`SKILL.md` What NOT to do), logged as today.

### Context file — new trigger

Adds one trigger to "Created only on trigger": **`bc plan` and `bc build` always write the file.**
`bc understand` writes only on the existing triggers. `/breadcrumbs` auto-flow is unchanged
(trigger-only), so lite and short stories still produce no file.

Why: a command can run in a fresh session; without the file `bc build` has no plan to read.

## 2. Test-first, minimal

### Rule (Step 3.4 becomes 3.4 red → green)

Per task, before any implementation edit:

1. **Red:** write the task's smoke test (from 2.4), run it, confirm it fails *for the expected reason*
   (missing route/function/element, wrong value — not a syntax or import error). Task Log gets
   `Red: <test> — <failure reason, one line>`.
2. **Green:** implement until it passes. `Verified:` as today.
3. **Frozen:** after the red run, the test's assertions don't change this task. A test that needs
   changing → Scope Change (3.7), never a silent edit. Setup/fixture plumbing may change; assertions may not.

Read exit codes and stderr, not printed summaries.

### What "minimal" means

| Story / layer | Smoke test |
|---|---|
| Backend endpoint touched | one per endpoint: happy path, status + response shape vs contract fixture. Error case only if the story names one |
| Frontend screen touched | one per screen: renders with fixture data, key element visible |
| Bug fix | regression test, red on the unfixed code |
| Refactor | characterization smoke test first, own commit, read-only for the story |
| Copy/config | one assertion on the new value |

Fewer tests, not weaker ones: a smoke test that still passes with the feature deleted doesn't count —
part of 3.4's self-review.

Step 2.4 shrinks to match: list one smoke case per endpoint/screen/fix, mapped to its task.
Full suites at 3.8 unchanged (backend + frontend, named, counted).

### Opt-in hook

`hooks/freeze-tests.mjs`, PreToolUse on `Edit|Write`: denies edits to test files recorded as frozen
for the current task (read from the context file's Task Log `Red:` lines). Off by default; enabled
per repo via plugin settings. Without it, the rule is enforced by the skill text and the scenario
checks only.

## 3. Contract-first (backend + frontend stories)

Applies when the story touches both layers. Monorepo detected by `pnpm-workspace.yaml`,
`turbo.json`, `nx.json`, or a `workspaces` field; also applies to separate-repo FE/BE when the
story spans both. Backend-only / frontend-only stories skip it.

### Task order

1. **Contract task** — request/response/error shapes where the repo already keeps shared types
   (workspace package, OpenAPI, zod; none → co-located types file), plus **one fixture file**:
   a canonical example response. No logic.
2. **Backend task(s)** — red: smoke test calls the endpoint, asserts status + shape against the fixture.
   Green: implement.
3. **Frontend task(s)** — red: smoke test renders with the *same fixture* as mock data, asserts key
   element. Green: implement.

Shared fixture = drift detector: backend changes shape → its smoke test fails; frontend expects a field
the contract lacks → its smoke test fails. No contract-testing tool needed.

### Contract frozen after task 1

Any contract change after task 1 → Scope Change, both smoke tests re-run.

### Step 1 addition

For BE+FE stories, Step 1 asks (layman register) what the screen shows, so the contract comes from
the user's view, not the table. Avoids backend-first returning the wrong fields.

### Step 2 changes

- 2.2's "Cross-team surface → agree the contract" becomes the contract task, not a note.
- 2.6 Sequencing: contract → BE → FE is the default order for BE+FE stories.
- 2.7 caps: the contract task counts toward the cap.

## Implemented differently

- **No `core.md` split.** `SKILL.md` already is the shared core (~80 lines); commands load it plus their step file. A split only complicated the Windsurf cap and pointer rewriting.
- **Command list lives in `scripts/build-platforms.mjs`**, not one source file per command: each command is a one-line pointer to the `SKILL.md` Step commands table, which holds Needs and next-command.
- **Freeze hook protects across tasks, not within one.** The Task Log entry (with `Red:`) is written after the task, so the hook sees a test as frozen from the next task on; within the task the skill rule holds. Unfreeze = the path named in a Scope Changes entry.
